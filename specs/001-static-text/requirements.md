# 001: static text requirements

**Status:** Implemented and verified for the bounded static-text slice. User approval recorded 2026-10-07 via the implementation plan; covers existing R1–R7 requirements, design, and T1–T7 tasks. Actual results and limitations are recorded in [verification](verification.md).

This record describes the historical Feature 001 slice. [Feature 003](../003-inline-formatting/requirements.md), separately approved on 2026-10-07, supersedes its literal-inline behavior for paragraphs/headings and adds inlineCodeFont. Feature 001 verification remains historical evidence.

## Scope and standards

Provide static paragraphs and ATX H1–H6 through native Qt Quick blocks. Supported structural rules follow [CommonMark 0.31.2](https://spec.commonmark.org/0.31.2/#atx-headings); unsupported block and inline syntax uses the explicitly bounded literal fallback below. This slice is not CommonMark conformant. See [standards](../standards.md).

| ID | Requirement and observable acceptance criterion |
| --- | --- |
| R1 | `MarkdownView.markdown` is a Unicode string, default empty. LF, CRLF, and lone CR are equivalent line endings. Empty lines and lines containing only ASCII spaces/tabs separate paragraphs. Consecutive ordinary nonblank lines form one paragraph. In ordinary paragraphs, remove leading/trailing ASCII spaces/tabs on each line and join lines with one space; preserve internal spaces/tabs and all other Unicode characters. Replace U+0000 with U+FFFD before parsing; no Unicode normalization is performed. |
| R2 | Outside protected fences, ATX headings allow zero to three columns of indentation, counting tabs at four-column stops. One through six opening `#` characters must be followed by ASCII space/tab or end of line. Strip indentation, opening markers, and surrounding ASCII spaces/tabs. Remove an optional closing run of `#` only when preceded by ASCII space/tab and followed only by ASCII spaces/tabs. No escape processing is performed. Headings interrupt paragraphs without a blank line; marker-only headings remain empty heading blocks. Four-column indentation, `#title`, and seven opening markers are ordinary fallback text. Setext headings are unsupported. |
| R3 | Render every block once in source order. Paragraphs and headings display plain literal text: emphasis, code spans, escapes, entities, HTML, links, images, lists, quotes, thematic breaks, and Setext markers remain visible punctuation. Unsupported lines use R1 paragraph rules; only R2 headings and protected fences interrupt paragraphs. A protected fence follows the opening/closing recognition rules in design and becomes one literal fallback block including delimiters, info text, indentation, interior blank lines, and line breaks. No headings are recognized within it. Unclosed fences protect through end of input. No code styling or inline semantics are implied. |
| R4 | The host supplies view width; effective layout width is `max(0, width)`. Blocks wrap within positive width, including unbroken words; an indivisible glyph/cluster wider than the view may overhang as documented in design. Read-only `contentHeight` is total laid-out block height plus gaps; `implicitHeight` equals it. `implicitWidth` is zero: no preferred horizontal size is supplied. At nonpositive width, contentHeight is zero and text layout waits for positive width. Explicit height neither changes contentHeight nor enables scrolling. Empty headings reserve one line in their heading font. Width/style changes recompute layout without changing block order/content. |
| R5 | `MarkdownView.style` accepts a `MarkdownStyle` object defined in design. Body and independent H1–H6 font/color properties plus block spacing provide neutral defaults. Runtime field changes, style replacement, shared styles, and reset to null update existing content and height without reparsing. Host themes are optional and never library dependencies. |
| R6 | New markdown replaces all prior content; identical assignments have identical observable output. Empty or ASCII-space/tab/line-ending-only input yields no blocks and zero contentHeight regardless of spacing. Replacement and style/layout changes settle by the next completed Qt Quick layout/polish cycle; no incremental reuse, block identity, or synchronous geometry guarantee is provided. |
| R7 | Use a private document model/parser and native Qt Quick components. The only new public QML types are MarkdownView and MarkdownStyle in QMarkdown. No HTML interpretation, resource loading, link activation, document-level HTML/QTextDocument/WebEngine renderer, or host-specific module is allowed. Shared/static installed consumers must instantiate both types and exercise rendering/style changes using only the installed package. |

R1 trimming matches supported ordinary paragraph handling, not unsupported indented-code semantics. Soft breaks display as spaces; hard-break markers remain literal under R3. NBSP and other Unicode whitespace do not separate paragraphs or qualify as heading separators. Fenced fallback deliberately preserves source layout instead of paragraph trimming; normalized line endings and U+0000 replacement still apply. A final source line ending inside a fence is retained, including after a closing fence.

## Out of scope

Inline formatting, semantic code blocks, lists, quotes, links, images, rules, tables, highlighting, selection/copy actions, streaming, extension renderers, resource fetching, HTML execution, and performance targets. Full CommonMark precedence and nested containers require later approved specifications.

See [design](design.md), [tasks](tasks.md), and [verification](verification.md). Implementation is authorized within this approved package.
