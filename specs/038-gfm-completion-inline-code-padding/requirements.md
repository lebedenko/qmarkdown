## Observable behavior

- R1: Add independent default-off `MarkdownView.tablesEnabled`, `tagFilterEnabled` and `gfmEnabled`. For task lists, strikethrough, extended autolinks, tables and tag filtering, effective enablement is `gfmEnabled || individualEnabled`. Never mutate individual values through the aggregate switch. Disabling it restores configured behavior. Equal assignments are inert; changed assignments preserve Markdown, emit only the assigned property's notification and use the established reparse/rebuild/resource-cancellation lifecycle.
- R2: Extend private bundled cmark with table recognition following [GFM 0.29-gfm §4.10](https://github.github.com/gfm/#tables-extension-). Retain one header row, zero or more body rows, column alignment and recursive inline semantics. Cover escaped pipes (including code), delimiter grammar, header/delimiter column-count agreement, missing/excess body cells and block termination. Preserve tables inside lists and quotes. Disabled parsing retains CommonMark 0.31.2 behavior.
- R3: Apply case-insensitive [GFM §6.11](https://github.github.com/gfm/#disallowed-raw-html-extension-) filtering to raw HTML semantics for title, textarea, style, xmp, iframe, noembed, noframes, script and plaintext. Retain original spelling in owned nodes and native literal presentation; retain a separate private filtered representation for semantic verification. Filtering concerns HTML-output interpretation; introduce no production HTML renderer or sanitizer claim.
- R4: Render native Qt Quick tables at containing width with equal column allocation, wrapped inline content and row height determined by the tallest cell. Honor left/center/right alignment; headers are bold. Reuse links, emphasis, code, strikethrough and resource-controlled image presentation. Hosts own navigation and scrolling. No internal scrolling; existing indivisible-glyph overflow at extreme widths remains a documented limitation.
- R5: Add grouped `style.table.headerForeground`, `headerBackground`, `bodyBackground`, `borderColor`, `borderWidth`, `horizontalPadding` and `verticalPadding`, following existing overrides, notifications and resets. Defaults in every preset: inherited foreground, transparent surfaces/borders, zero border width, 4/2 logical-pixel padding. Styles update live.
- R6: Add grouped `style.inlineCode.horizontalPadding` and `verticalPadding`, defaulting to 4/2 logical pixels in every preset, including Legacy and Minimal. Follow existing override/reset/notification behavior. Normalize negative/nonfinite layout metrics to zero, consistent with renderer metric conventions. Reserve horizontal layout space, expand backgrounds and increase line height where needed even for transparent backgrounds. Each wrapped visual fragment receives padding. Prevent overlap with adjacent text and lines. Zero padding restores previous spacing.
- R7: Keep semantic text and UTF-16 ranges unchanged. Maintain explicit geometry/source mapping for links; padding around linked code activates its enclosing link. Preserve bidi shaping and grapheme boundaries using QTextLayout. Require a successful wrapping, bidi and hit-testing prototype before committing the detailed production renderer design. If gates fail, revise the design for approval; paint-only padding is insufficient.
- R8: Prepare package 1.6.0 / QML 1.6, preserving supported historical 1.x imports and package requests. Extend shared-linked, plugin-only and static installed consumers and exact/future-version rejection matrices. Update playground controls, styling/extension guides, changelog, standards, roadmap and release notes; document the intentional default inline layout change. Describe support for all five extensions with CommonMark 0.31.2 core; exact GFM 0.29-gfm conformance requires separate evidence.
- R9: Pin attributed official table and tag-filter examples with offline fixtures/checksums and independently authored model expectations. Verify all 32 independent extension combinations and both aggregate states, precedence/restoration, notifications, replacement and resource cancellation. Verify native table and inline geometry/interaction. Run focused checks before unchanged strict 652-example CommonMark gate, shared/static tests, lint, symbol privacy, benchmarks and configured Qt 6.8.0/6.12.0 checks.
- R10: Keep implementation, tests, documentation and evidence together in one focused PR per meaningful change, squash merged under existing protections when authorized. Release delivery must verify exact final Ubuntu/Arch package bytes, tag v1.6.0, publish verified bytes and independently accept downloaded packages only after explicit delivery/publication authorization. Retain checksums and compact release evidence; no automatic evidence-only initiative.

Architectural limits: independent library, private parser → owned semantic model → native Qt Quick components. No new dependencies, HoloNight integration, document-level HTML, QTextDocument or WebEngine rendering.
